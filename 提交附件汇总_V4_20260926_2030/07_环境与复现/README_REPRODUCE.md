# 复现说明

## 环境

建议使用 `python-version.txt` 所示 Python 版本，并执行：

```bash
python -m pip install -r requirements-lock.txt
```

正式运行还需要主办方提供的原始 A/B/C 数据。原始数据没有复制到本目录；在原项目中的只读位置为 `F题/real_attachments/`。

## 复现顺序

1. Q1：`02_源码/01_Q1质量主流程`，随后运行 `02_源码/02_Q1规则敏感性` 与 `02_源码/08_Q1最终验证`。
2. Q2：依次使用 `02_源码/03_Q2来源内质量`、`04_Q2配比与尺度桥接`、`05_Q2集成合同` 和 `09_Q2最终闭合`。
3. Q3：使用 `02_源码/06_Q3预算优化`，输入以 `01_科学冻结/T06_RESULT_FREEZE.md` 和 Q2 集成合同为准。
4. Q4：使用 `02_源码/07_Q4_Loss_Benchmark桥接` 和 `10_Q4最终闭合`。
5. 论文图：使用 `04_图表` 内脚本与最小源数据。

各步骤的确切输入文件、支持范围和资格词记录在 `06_核验与正式run证据` 中。大型行级结果未随包复制，因此本目录定位为“核心结果可审查、正式逻辑可追溯”的轻量附件，而非离线复制全部原始运行目录。

## 重要限制

- 不允许把 A 侧 `Q_baseline` 与 B 侧 `Q_score` 直接视为同一尺度。
- 不允许把 Q4 的 `SCENARIO_ONLY_UNVALIDATED` 情景写成已验证预测。
- 不允许把 0/0 的贡献占比写成“规模贡献为0”。
- Open LLM Leaderboard 原始快照因许可未确认未随包分发。
